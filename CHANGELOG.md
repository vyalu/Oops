# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
проект придерживается [семантического версионирования](https://semver.org/lang/ru/).

- Новый README: баннер, анимированная демонстрация, скриншоты в светлой и тёмной теме, на телефоне и в разных цветах. Картинки — в `docs/`, `docs/social-preview.jpg` можно поставить превью репозитория (Settings → Social preview).

### Исправлено
- График «Динамика расходов» не растягивался на всю ширину панели — подписи месяцев не совпадали с точками.
- В карточке подписки кнопки внизу вылезали за край окна (окно стало шире, кнопки переносятся при нехватке места).

## [1.2.2] — 2026-10-04

Обновление оформления. Данные и логика не менялись.

### Изменено
- Обновлённый стиль: единые карточки и панели, цветные бейджи типов подписок с иконками, таблицы с заголовками-капителью, тёмные тосты, размытый фон под модальными окнами, заметная обводка фокуса с клавиатуры.
- Суммы набраны пропорциональным шрифтом с табличными цифрами — без «дыр» между разрядами.
- Валюта везде показывается символом: ₽, $, € (раньше местами был код RUB).
- Основной цвет по умолчанию — «Терракота» (если цвет ещё не выбирался вручную).
- Кнопки темы — иконки луны и солнца вместо символов, одинаковые во всех ОС.
- На карточке подписки показывается дата следующего платежа.
- Сетка карточек подписок и контрагентов подстраивается под ширину экрана; ячейки календаря фиксированной высоты.

### Добавлено
- Плотность интерфейса «Обычно / Компактно» в «Система → Оформление».

### Исправлено
- Кнопки ✎/× в справочниках могли вставать столбиком.
- Картинки без адреса больше не запрашивают текущую страницу.

## [1.2.1] — 2026-10-03

Исправительный релиз: ошибки в расчёте дат и уведомлениях, безопасность, надёжность бэкапов.
Данные и настройки сохраняются, повторно ничего настраивать не нужно.

### Исправлено
- **Даты платежей.** Сервер брал число платежа из скрытой «даты следующего платежа» (форма заполняла её датой создания), а не из «Дня списания». Теперь напоминания, дашборд, «Отправить ближайшие» и календарь считают даты одинаково — по дню списания, с учётом периодичности (месяц/год, «каждые N периодов»).
- Платёж 31-го числа больше не «съезжает» на 28-е после февраля.
- «Отметить оплату» после даты платежа закрывала уже следующий период. Теперь закрывается просроченный платёж.
- Просрочка для подписок с ручной оплатой: ежедневное напоминание «Просрочено N дн.», пока платёж не отмечен оплаченным; просроченные подписки видны на дашборде. Старые прошедшие платежи при обновлении считаются закрытыми — лавины уведомлений не будет.
- Напоминание об отмене подписки приходило каждый час — теперь раз в сутки.
- Webhook с JSON-шаблоном ломался на кавычках и переносах строк в названиях (например, `ООО "Ромашка"`) — значения экранируются.
- Telegram: сообщения с `_` или `*` в названии не отправлялись (разметка переведена на HTML).
- E-mail на порту 465 (SSL) не работал при включённом TLS.
- Кнопка «Тест» канала уведомлений показывала успех даже при ошибке отправки.
- В уведомлениях дата `{{subscription_date}}` теперь — дата платежа, о котором уведомление.
- Отрицательный баланс из API (`-50`, `−50 ₽`) читался как положительный; из длинных ответов (страница ошибки) больше не выдёргивается случайное число.
- Дашборд «Низкий баланс» учитывает счета с ежедневным списанием, правила совпадают с уведомлениями; показывается валюта счёта.
- Списание баланса в 29–31 число в коротких месяцах не происходило; пропущенное из-за выключенного сервера списание догоняется позже в том же месяце.
- Экспорт/импорт: в бэкап добавлены документы и история расходов. Импорт старого бэкапа больше не удаляет загруженные документы.
- Бэкапы БД делаются консистентно (SQLite backup API), восстановление корректно при работающем приложении; копии «перед восстановлением» хранятся только 3 последние.
- Часовой пояс планировщика берётся из переменной `TZ`.

### Безопасность
- Наблюдатель (viewer) больше не видит URL API баланса (в них логины и ключи) и настройки каналов уведомлений (токены, пароли SMTP).
- Исправлена возможность внедрить HTML/скрипт через поле «URL» и «Примечания» в карточке подписки; ссылки открываются только для http/https.
- Загруженные SVG-логотипы и иконки не могут выполнять скрипты при прямом открытии.
- Убран CORS `*` с передачей cookie.
- Ограничение подбора пароля: 10 неудачных попыток входа с одного IP за 15 минут.
- Минимальная длина нового пароля — 6 символов (действующие пароли продолжают работать).
- Ограничение размера загружаемого документа (50 МБ, переменная `OOPS_MAX_UPLOAD_MB`).
- Токены каналов уведомлений больше не пишутся в логи.
- Распаковка архива обновления защищена от выхода за пределы папки.
- Библиотека python-jose заменена на PyJWT; обновлены FastAPI/Starlette и python-multipart. Текущие сессии остаются действительными.
- Приложение в контейнере работает от обычного пользователя (uid 1000), а не от root.

### Изменено
- `docker-compose.yml` — простой запуск в локальной сети на порту 8383; вариант с HTTPS и Caddy вынесен в `docker-compose.https.yml`.
- В разделе «Система» для установки из готового образа показывается подсказка, как обновляться.
- Обновление архивом через интерфейс тоже работает, но новые библиотеки и запуск не от root применяются только после пересборки (`docker compose up -d --build`).

## [1.2.0] — 2026-07-06

### Добавлено
- Полностью новый визуальный стиль: тёплая светлая и тёмная темы, шрифты IBM Plex, обновлённые карточки и панели.
- Выбор основного цвета интерфейса (8 акцентов) и переключение светлой/тёмной темы в разделе «Система → Оформление». Логотип и все акценты меняются вместе с выбором.
- Новый тип подписки «Баланс (Ежедневное списание)» — для сервисов с посуточным списанием; стоимость указывается за месяц, порог уведомления настраивается в днях.
- Дашборд переработан: кольцо «Доли по организациям», график динамики расходов (копит историю по месяцам), горизонтальные бары по организациям, KPI «К оплате за 30 дней».
- Контекстные подсказки (?) у полей формы подписки с понятными объяснениями.
- Экран загрузки с анимированным логотипом.
- В календаре оплаченные платежи месяца отмечаются зачёркиванием и галочкой.
- Документация: инструкции по смене порта и доступу по доменному имени.

### Изменено
- Типы подписок переименованы для ясности: «Баланс (Периодическое списание)» и «Баланс (Ежедневное списание)».
- Меню сгруппировано в выпадающие разделы «Справочники» и «Администрирование», шапка в одну строку.
- Все цвета переведены на единую систему тем — интерфейс единообразен на всех экранах.

### Исправлено
- Корректный расчёт дат для годовых, недельных и других непомесячных циклов (напоминания и «предстоящие платежи»).
- После отметки оплаты платёж корректно исчезает из предстоящих до следующего периода.
- Устранены ошибки отрисовки графиков (SVG) и мелькание темы при загрузке страницы.

## [1.0.0] — 2026-05-23

Первый публичный релиз. Самохостящийся трекер подписок и платежей для организаций.

### Основные возможности

**Учёт**
- Несколько организаций (юр. лиц) с раздельным учётом расходов.
- Контрагенты с логотипами: загрузка файла, авто-favicon с сайта, поиск с созданием на лету.
- Сотрудники как ответственные за подписки.
- Три типа записей: «Подписка» (регулярная оплата в день месяца), «Счёт/Баланс» (пополняемый счёт), «Разовый платёж».
- Категории и способы оплаты с иконками (встроенные SVG).

**Балансы и автоматизация**
- Получение баланса из внешних API: SMS.ru, BILLmanager (FirstVDS / FirstDedic) и произвольные JSON-источники с гибким парсером (вложенные пути, индексы массивов, валюта в строке).
- Обновление балансов по расписанию (каждые 30 минут).
- Списание баланса в день списания для счетов без API.
- Алерт при низком балансе (раз в день, пока баланс недостаточен).

**Уведомления**
- Четыре канала: Webhook, E-mail (SMTP), Telegram, Bitrix24.
- Напоминания о платеже: настраиваемое «начать напоминать за N дней», далее ежедневно (включая просрочку), пока оплата не отмечена.
- Флаг «Продлевается автоматически»: только предупреждение заранее, без напоминаний о просрочке.
- Кнопка «Отметить оплату» закрывает текущий платёжный период.
- Журнал доставки уведомлений с историей попыток.
- Устойчивость к перезапускам: пропущенные напоминания догоняются.

**Интерфейс**
- Два режима отображения подписок: крупные карточки и компактный список с раскрытием.
- Дашборд: предстоящие платежи, низкий баланс, расходы по организациям.
- Тёмная и светлая темы.
- Роли: admin / manager / viewer.

**Данные и эксплуатация**
- Импорт/экспорт: полный ZIP-бэкап (БД + логотипы + JSON), импорт из бэкапа Wallos.
- Восстановление из бэкапа через интерфейс.
- Автоматический бэкап БД раз в неделю; бэкап БД перед каждым обновлением.
- Обновление через веб-интерфейс загрузкой .tar.gz (без SSH).
- Healthcheck и ротация логов в Docker.

**Безопасность**
- HTTPS «из коробки» через встроенный Caddy (Let's Encrypt или самоподписанный для локальной сети).
- Автогенерация секретного ключа сессий при первом запуске.
- Secure-куки за HTTPS.
- Требование сменить стандартный пароль admin при первом входе.

**Развёртывание**
- Один Docker-контейнер приложения + Caddy. docker compose up -d --build.
- Полностью автономно: фронтенд-библиотеки и стили хостятся локально, работает без доступа в интернет.
